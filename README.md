# Livestock ERP — Phase 1 + Phase 2 MVP

Offline-first dairy farm management PWA. Built with Next.js, Supabase, and Dexie (IndexedDB).

See `SETUP_GUIDE.docx` for full, non-technical, step-by-step instructions to deploy this
(Supabase project, schema, phone-based login, Vercel hosting, installing on a phone).

## Database setup

Run, in order, in the Supabase SQL Editor:
1. `supabase/schema.sql` — full schema (Phase 1 + Phase 2, all in one file for fresh installs)

If you already deployed an earlier version and are only adding what's new since, instead run
just the migration(s) you're missing, in order:
2. `supabase/migrations/002_breeding_reminders.sql`
3. `supabase/migrations/003_customer_ledger.sql`
4. `supabase/migrations/004_notification_engine.sql`

## What's implemented

### Phase 1
- Phone + OTP sign-in, once, then offline PIN unlock on that device
- Farm onboarding wizard, animal registration
- Offline milk entry, health logging (Swahili/English picklist), feed logging
- Manual cost/revenue entry with a live profit dashboard
- Team/role management, installable PWA, tiered offline sync queue

### Phase 2
- **Breeding & Calving Calendar** — offline heat/service/pregnancy-check logging from
  Worker → Breeding. When the calf is registered from Worker → Animal → Birth, the app
  auto-suggests the dam from confirmed pregnancies and, on save, closes her breeding record
  and flips her status to lactating — no separate step needed.
- **Per-Animal Profitability** — Manager → Profitability ranks every animal by profit over the
  last 30/90 days (feed + vet costs are exact per-animal; milk revenue is fairly allocated by
  litres produced, since milk is usually sold in bulk).
- **Customer/Debtor Ledger** — Manager → Customers tracks milk buyers, deliveries, payments,
  running balances, and a per-customer statement. Deliveries auto-post to the revenue table via
  a database trigger, so the finance dashboard and profitability numbers stay in sync automatically.
- **In-App Notification Engine** (replaces the old unused SMS notification stub — see note below) —
  a bell icon with an unread badge on both Worker and Manager headers, plus a full
  Manager → Notifications page with type filters (Alerts / Reminders / Warnings) and mark-as-read.
  Notifications are generated by a `generate_notifications()` Postgres function that scans
  breeding, health, feed inventory, and finance conditions — called opportunistically by the
  client whenever it's online (no cron job, no external service). Read entirely from the
  offline cache the rest of the time. The `channel` column on `notifications` is reserved
  (`'in_app'` / `'sms'` / `'email'`) for future delivery methods, but only in-app is implemented now.

### A note on Twilio

Twilio was never used for alerts in this system — there was no SMS-based notification code to
remove. Its only real role is in the phone/OTP **login** flow (Supabase Auth's phone provider,
configured with Twilio Verify per the setup guide). That's authentication, not alerting, and
hasn't been changed. If you'd like phone login to use something other than Twilio, that's a
separate decision — happy to help with it, just say the word.

## What's still postponed (per current scope)

SMS/email delivery of notifications, M-Pesa integration, multi-farm support, advanced analytics.

## Local development

```bash
npm install
cp .env.local.example .env.local   # fill in your Supabase URL + anon key
npm run dev
```

## Project structure

```
app/manager/breeding/            Breeding & calving reminders dashboard
app/manager/profitability/       Per-animal profit ranking
app/manager/customers/           Debtor ledger (list + per-customer statement)
app/manager/notifications/       Full notification list, filterable by type
app/worker/breeding/             Offline heat / service / pregnancy-check entry
components/NotificationBell.js   Bell + unread badge + dropdown, used on both headers
lib/notifications.js             Refresh (calls generate_notifications RPC), offline mark-as-read
supabase/schema.sql              Full schema (run this for a fresh install)
supabase/migrations/             Incremental migrations (for upgrading an existing install)
```
